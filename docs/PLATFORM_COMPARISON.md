# Isaac Sim vs Isaac Lab for the Trex walking task

Two stacks run the same task. The Isaac Sim stack is kept working as the fallback.

| | Isaac Sim stack (original, fallback) | Isaac Lab port |
|---|---|---|
| code | `walk_rl/env.py` (`TrexWalkEnv`) | `walk_lab/env.py` (`TrexLabDirectEnv` + `TrexLabWalkEnv`) |
| simulator API | `isaacsim.core.experimental` Articulation, GridCloner, raw PhysX views | Isaac Lab 3.0.0-beta2.patch1 `DirectRLEnv`, `InteractiveScene`, `Articulation` + implicit actuators, contact sensors, wrench composer |
| conda env | `isaac6` (Isaac Sim 6.0.1, torch 2.11) | `isaaclab6` (clone of isaac6 + Isaac Lab from `~/IsaacLab3`, rsl-rl-lib 5.0.1) |
| trainers | walk_rl PPO (`walk_rl/train.py`) | walk_rl PPO (`walk_rl/train.py --backend lab`) or rsl_rl (`walk_lab/train_rsl.py`) |

## What is shared, so the comparison measures the platform

- **Task logic**: `walk_rl/task_core.py` (`TrexTaskCore`) holds everything that defines the task:
  - servo model (delay, low-pass, quantization, speed-limited ramp);
  - commands and gait clock;
  - all rewards and terminations;
  - observations, history and heading;
  - harness and push curricula;
  - per-episode sensor randomization;
  - domain-randomization sampling.

  Each stack implements only the `_sim_*` / `_dr_*` hooks: read state, write targets, teleport the ankle, apply wrench, reset, and set friction/mass/CoM/gains/effort.
- **Refactor check**: the Isaac Sim stack after the refactor is **bit-identical** to before it. `walk_rl/trace_env.py` ran 150 steps on CPU physics with the v8d policy, covering resets, harness, pushes and a manual kick: max diff 0.0.
- **Robot**: `walk_lab/bake_usd.py` writes `_converted_usd/trex_lab/trex_lab.usd`. It uses the same URDF import cache and the same `apply_robot_config` (limits, torque caps, base mass) that walk_rl applies live. The file stores a hash of `robot_config.yaml` + URDF, and the Lab env refuses a stale bake.
- **Physics settings**: `walk_lab/physics_dump.py` diffs every authored physics attribute of the scene, ground, robot prims, joints and materials. Only two differences remain:
  - explicit gravity (9.81, the same value);
  - runtime velocity state.

  Matching took four deliberate steps (see "Isaac Lab pitfalls").
- **Trace parity**: the same 150-step trace on the Lab port is **bit-identical** to the Isaac Sim stack on CPU physics. It covers harness, pushes, kicks, 48 resets and domain randomization, and every observation, reward, done, base position and joint position has max diff 0.0. The Lab port reproduces the original stack exactly, not just approximately. Before the harness fix below, the only difference was a 0.09% reward drift.
- **Evaluation**: `walk_rl/evaluate.py --backend {isaacsim,lab}` runs the identical suite on either simulator. Every policy is judged on both, so "trained on X, tested on Y" is visible.
- **Same config, seed, env count and iteration count** for the training runs below.

## Isaac Lab pitfalls found during the port (each would have silently changed the task)

1. **`activate_contact_sensors=True` skips nested rigid bodies.** It stops descending at the first rigid body ("nested rigid bodies are not allowed by SDK"). Our URDF import nests them (`base_link/left_femur/left_tibia/left_ankle/left_foot`), so only `base_link` got a contact reporter. It also sets every body's sleep threshold to 0, which walk_rl does not. The fix applies `PhysxContactReportAPI` to exactly walk_rl's links instead.
2. **`ContactSensor` data is zeroed on reset.** PhysX itself keeps reporting the stale pre-teleport force, and that is the bug behind v6's "terminate at ep_len 1". Reading the sensor's buffered data would arm the stale force. The port reads raw `contact_view.get_net_contact_forces` like walk_rl, so `task_core`'s stale-contact handling works unchanged.
3. **`PhysxCfg()` authors its own scene values.** For example, bounce threshold 0.5 m/s against the PhysX schema default of 0 that the Isaac Sim stack runs with. The port sets them explicitly.
4. **The `GroundPlane` extension isn't loaded.** Isaac Lab's app launcher doesn't load `isaacsim.core.experimental.objects`. The port makes the identical `PhysicsSchemaTools.addGroundPlane` call.
5. **The wrench composer adds rounding.** Isaac Lab's composer converts a world-frame force to the body frame before making the same PhysX call. That was the only thing separating the stacks in trace tests, giving a 0.09% reward drift over 150 steps. The port now makes the PhysX call directly for the harness.
6. Smaller items:
   - rsl_rl collects in `torch.inference_mode()`, so env buffers are inference tensors afterwards.
   - `DirectRLEnv.extras` persists across steps, so a `log` entry must be cleared or rsl_rl logs it every step.
   - rsl_rl 5 needs `handle_deprecated_rsl_rl_cfg` on Isaac Lab's runner config.

## Notes for interpreting results

- Isaac Lab 3.0 is a **beta** release, and patch1 is the build that supports Isaac Sim 6.0.1. Its install reports pip conflicts (`coverage`, `packaging`) that have not affected anything so far.
- Throughput numbers are only valid on an idle GPU. The GPU is shared with another agent's jobs, and any overlap is noted in the results.
- Training metrics are not the fall rate. Policies are compared on `evaluate.py` only (see `docs/WALK_TASK.md`).
- Early CPU-physics data point, measured while v8e was training so only indicative: 32 envs, Isaac Sim stack 294 ms/step against Isaac Lab 88 ms/step. The Isaac Lab app also took about 140 MiB of GPU memory against 1.3 GB, because its launcher starts a lighter Kit experience without the RTX renderer.
